Lỗi: Phía front, eval không đo hai vế spec hứa: (1) cờ build **thiếu** thì tắt; (2) không file cấu hình nào trong repo front bật `VITE_ADMIN_OPEN`. `check_front.cjs` hàm `build()` luôn đặt `VITE_ADMIN_OPEN: ''` vào môi trường build (case 6 lặp `''`, `'0'`, `'true'`, `'yes'`, `' 1'`; (b), (c) cũng nhận `''`), nên không lần build nào để biến thật sự vắng mặt. Vite cho biến trong process.env thắng file `.env*`, nên chuỗi rỗng ép vào còn che luôn file `.env*` của repo. Phần quét cấu hình của `check_3` chỉ quét repo back. Production (Vercel) build **không có** biến này, nên đây đúng là trường hợp eval bỏ trống.

Bằng chứng (dựng lại trên worktree tạm `/tmp/t188-crit-front` từ front main 26c5758, không đụng checkout thật):

- Đột biến M2: kiểm cờ đúng `=== '1'` nhưng commit `.env.production` chứa `VITE_ADMIN_OPEN=1`. `check_5` PASS, `check_6` PASS.
- Chạy lại M2 bằng bản sao check_front chỉ khác một chỗ là xoá `VITE_ADMIN_OPEN` khỏi env build (build giống Vercel), case 6 (c) ĐỎ: "cờ không đặt + có khoá Clerk: ... GET /api/admin/me, GET /api/admin/vendor-enrich". Bỏ `.env.production` thì bản sao đó PASS. Nghĩa là eval sửa vẫn phân biệt được đúng/sai.

  a. Thiếu biến = tắt (đúng spec): production đóng như hôm nay.
  b. Thiếu biến = mở (M1): deploy là `?admin=` mở ngay trên production cho bất kỳ ai. Capu chưa bật gì cả, và Thành viên / Hộp kết nối (email, SĐT) lộ ra (nửa front; API còn chặn nếu Worker tắt, nhưng chỉ cần Capu bật Worker là lộ cả, ngược ý "Capu bật cả hai").

Kỳ vọng theo brief/ADR-116: "mặc định TẮT trong code; Capu tự bật ở Cloudflare/Vercel". Spec đã viết đúng điều này (Định nghĩa + Hành vi 6). Chỗ thiếu là eval.
