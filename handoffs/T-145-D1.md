Lỗi: (1) chính eval của spec làm đỏ bất biến tầng 2 `_shared/inv-001`; (2) eval 1 và 3 đo thư mục làm việc lúc gọi `git push` thay vì nội dung được đẩy đi, nên một bản workflow đẩy thêm `tasks.json`/`events.json`/`roster.json` vẫn qua cả hai; (3) git giả luôn thành công, nên một bản workflow chắc chắn đỏ trên runner thật vẫn qua tiêu chí 1. Đây đúng là bài học T-118/T-127/T-134 mà brief nhắc tới.

Bằng chứng:
- `python3 scripts/gate.py T-145`: `[2] FAIL eval/invariants/_shared/inv-001-khong-secret-trong-repo.sh`, trúng `eval/T-145/_wf.py:11: TOKEN = "ghp_<token-giả-đã-che>"`, khớp mẫu `ghp_[A-Za-z0-9]{30,}`. Khi file này được commit, mọi việc trong công ty sẽ đỏ tầng 2. Gate gợi ý `--kind spec`.
- Đã thử bước đẩy (env `DASH_TOKEN: ${{ secrets.DASHBOARD_DATA_TOKEN }}`) trên 9 bản workflow, chạy qua `T145_WORKFLOW=…`:
  - Đỏ đúng như mong đợi: in token (`echo "token=$DASH_TOKEN"`), in URL push có token (`echo "push $U"`), `HEAD:main`, `HEAD:gh-pages`, push thêm lần hai vào main.
  - XANH nhưng sai, bản "commit hết rồi xoá": `cp "$RUNNER_TEMP/out/"*.json "$D/"; git add -A; git commit; find . -name '*.json' ! -name dashboard.json -delete; git push …`. check_1 PASS, check_3 PASS. Dựng lại bằng git thật với một bare repo: `ls-tree dashboard-data` cho ra `dashboard.json tasks.json`. Như vậy bản này đẩy cả 4 file, trái với câu 3 của spec.
  - XANH nhưng hỏng trên runner, bản "không -b": `git init -q` (nhánh mặc định master) rồi `git push -f URL dashboard-data`. Git thật trả `error: src refspec dashboard-data does not match any` và thoát 1. Câu 3 của spec cho phép refspec dạng `dashboard-data`, nên spec cũng chấp nhận cách cài này.
  - XANH nhưng hỏng trên runner, bản "thiếu git config user": git thật trả `Author identity unknown` và thoát 128 ở bước commit.

Ba cách hiểu câu "thư mục … chỉ chứa đúng một file dashboard.json … commit một lần, rồi … git push":
  a) chỉ chép `dashboard.json` vào thư mục rồi commit. Đẩy đi 1 file.
  b) chép cả `out/` vào, chỉ `git add dashboard.json`. Đẩy đi 1 file, nhưng lúc push thư mục có 4 file nên eval đỏ, dù hành vi vẫn đúng.
  c) chép cả `out/`, `add -A`, commit, xoá bớt rồi push. Đẩy đi 4 file, nhưng eval xanh.
Ở b và c, cái người ngoài thấy trên nhánh `dashboard-data` ngược hẳn với kết quả eval. Hành vi phải đo bằng nội dung của ref sau khi đẩy, không phải bằng thư mục lúc gọi lệnh.

Kỳ vọng theo brief: "bước đẩy chạy nguyên văn với git giả … chỉ dữ liệu --public … không chạm nhánh main của repo dashboard". Eval phải đo cái thật sự nằm trên nhánh đích, và không được tự làm đỏ bể.

Ảnh hưởng: nếu merge, sổ cái đỏ tầng 2 cho mọi việc. Code Gate có thể cho qua bản workflow lộ thêm file trên repo công khai, hoặc bản xanh trong eval nhưng đỏ ngay lần chạy đầu tiên khi Capu đặt secret.
